# 단일 모델 학습 설계 (초안, 2026-10-17)

> 기록용 초안이다. 이후 연구는 Gemma 하나로 모든 것을 맡기는 대신 encoder와 Gemma를 결합하는 방향, 그리고 처음부터 만드는 모델로 갔다. 지금 상태는 [overview.md](overview.md)를 본다.

목표: Gemma 4 E2B 하나가 입력 판정, MONDO 연결, 장기 판정, 증상 검색을 모두 맡는다. 앱의 BioLORD 매칭과 SapBERT 인코더는 빠진다.
SapBERT 이름 벡터 95,437개는 표로만 남는다. 장기에서 ADC 경고로 가는 점수(MLP)는 언어 모델이 아니므로 그대로 둔다.

판정 기준(미리 정함, 2026-10-17 갱신): gold dev에서 seed 3개 평균으로

- 장기 13개 각각 F1 0.95 이상. 영어와 한국어 모두. 두 annotator의 장기별 일치도는 0.94~1.00이라 사람 수준의 목표다.
- 무효 입력 수락률 0.00.
- 증상 설명 검색은 목표에서 뺀다. 점수는 기록만 한다(프로필 문장에 과적합되기 쉬운 구조).

이 조건을 다 채우면 단일 모델을 기본 경로로 둔다. test는 마지막에 한 번만 본다. 누구나 같은 비교를 다시 돌릴 수 있게 `ml/reproduce_judge.py`가 학습부터 튜닝 전후 비교까지 한 번에 한다(`ml/docs/reproduce.md`).

## 0. 기록과 비교 (가장 먼저 지킬 것)

**학습 기록.** 모든 학습 실행은 카드 하나를 남긴다(`ml/results/tuning/<tag>.json`, `ml/tuning_ledger.py`).

- 카드에 들어가는 것:
  - 단계(`--stage`)와 메모(`--note`), 비교 기준 실행(`--compare-to`).
  - git 커밋과 커밋 안 된 변경 목록.
  - 학습이 읽은 모든 데이터 파일의 행 수와 sha256.
  - 설정 전부, 출력별 학습 항목 수, epoch별 손실, 고른 epoch, 보정값.
  - 학습 전 검사 결과, 내부 dev 결과, 벤치마크 점수.
- `ml/docs/tuning_log.md`는 카드에서 자동으로 만든다. 단계마다 "앞 실행 대비 바뀐 것"(데이터 파일, 설정)과 점수를 나란히 적는다.
- 그래서 어느 단계에서 어떤 데이터로 몇 점이 나왔는지를 나중에 그대로 되짚을 수 있다.
- 지난 실행 6개(0.6 기준, 반영 오류, 수정 데이터 × seed 2)는 이미 카드로 옮겼다.

**비교 벤치마크.** `ml/bench_judge.py`가 같은 질문으로 시스템을 채점한다.

- 시스템:
  - `base`: 튜닝 안 한 Gemma 4 E2B. 튜닝을 시작한 바로 그 revision이다.
  - `single`: 튜닝한 단일 모델.
  - `app`: 지금 파이프라인.
- 질문:
  - gold 600개(영어)와 같은 600개의 한국어판: 장기 F1, MONDO 개념 정답률, 무효·모호 수락률, 범주별 점수.
  - 증상 설명 → 질환.
- `base`는 few-shot 프롬프트로 질환명과 장기를 생성하게 하고, 이름을 MONDO 이름·동의어에 정확히 맞춰 연결한다.
  few-shot 예시는 gold·증상 평가에 없는 학습 프로필에서 골랐고, 실행할 때마다 겹치지 않는지 검사한다.
- `--table`은 시스템들을 한 표로 보여 주고, 기준 시스템과의 차이를 paired bootstrap으로 붙인다.
- 단계가 끝날 때마다 그 단계의 대표 모델을 벤치마크에 넣는다. 최종 비교는 `base` → 각 단계 → 최종 모델이다.

설계에 주는 것:

- **한국어:** 튜닝 효과가 아직 거의 없다. 한국어 데이터와 목표가 다음 단계의 중심이다.
- **개념 연결:** 튜닝 안 한 Gemma가 영어 이름을 생성한 뒤 맞추는 방식(0.435 / 0.409)이 튜닝한 align head(0.36 / 0.19)보다 낫다. 단일 모델의 연결은 "영어 표준명 생성 → MONDO 이름 맞춤"을 align과 함께 시험한다(§4).
- **증상 검색, 영어, 모호 입력:** 튜닝의 효과가 크다.

**S1 결과: 한국어 이름·표현 추가 (2026-10-18, seed 3개 평균, dev).**

추가한 데이터는 검토한 MONDO 한국어 이름 20,810개와 Haiku 한국어 표현 11,261개다. 한국어 학습 항목은 3.1만에서 7.1만으로 늘었다.

| | 영어 장기 F1 | 한국어 장기 F1 | 한국어 개념 |
|---|---|---|---|
| S0b (수정 데이터) | 0.883 | 0.771 | 0.19 |
| S1 | 0.879 | 0.775 | 0.25 |

한국어 장기 F1은 거의 그대로다. 원인을 따로 확인했다.

- **연결이 장기 판정을 망치지 않는다.** organ head만 쓰면 0.781, 연결 개념의 라벨만 쓰면 0.766이다.
- **연결 비교 정정.** 신뢰도 컷(0.7)을 없애면 튜닝 모델의 개념 정답률은 영어 0.535, 한국어 0.400이다. 튜닝 안 한 Gemma(0.435 / 0.409)보다 영어는 낫고 한국어는 비슷하다. 앞의 "튜닝 안 한 Gemma가 연결을 더 잘한다"는 컷 때문이었다.
- **한국어 dermatologic(0.39~0.45)의 틀린 23건 중 15건은 다계통 질환에 skin을 더한 것이다.** SLE, 사르코이드증, GPA, NF2가 그렇다. gold는 SLE를 infectious_immune만으로 적는다. 학습 라벨은 검토 GUIDE의 "직접 침범하는 장기를 모두"를 따른다.
- **라벨 기준 차이의 크기.** Opus가 학습 GUIDE대로 gold 개념 80개를 처음부터 라벨링한 결과(2차 검토의 숨은 대조 항목)는 gold와 macro F1 0.945다.
  - 장기를 더한 경우 14건, 뺀 경우 0건이다.
  - hepatic 0.86, cardiovascular 0.91, musculoskeletal 0.91이다.
  - 학습 기준을 완벽히 배운 모델도 gold 기준으로는 장기별 0.95에 못 미친다.
  - **장기별 0.95 목표 전에 라벨 기준을 하나로 맞춰야 한다.**

**학습 전 검사로 찾은 것 (2026-10-17).**

- **평가 질문이 정답과 함께 학습에 들어감:** gold 평가 질문 211개(질환명, 동의어, 약어)가 프로필 이름으로 학습에 들어가 있었다. gold 개념이라 organ·align 목표에서는 빠졌지만, valid와 sym 출력이 정답 개념과 함께 배웠다. 증상 평가 문장은 섞이지 않았다.
  - 이제 학습이 이런 항목을 빼고 그 수를 카드에 남긴다.
  - 0.6과 수정 데이터 모델의 점수는 이 부분만큼 낙관적일 수 있다. 다음 학습부터 깨끗하다.
- **약어가 다른 개념으로 학습됨:** 평가 질문과 같은 약어 122개가 드문 MONDO 개념으로 organ 학습에 들어가 있다. 예: `RLS` → Reunion island Larsen syndrome, `RA` → myelodysplastic syndrome.
  - 정답을 새는 것은 아니지만, 흔한 뜻과 반대로 가르친다. 0.6a에서 `RLS`를 놓친 원인 중 하나다.
  - §3에서 짧은 약어 동의어를 걸러 모호 입력으로 돌린다.
- **무효 입력 4배 반복이 동작하지 않음:** `gemma_judge2.py`는 무효 입력을 4번 넣지만, 바로 뒤의 중복 제거가 같은 텍스트를 하나로 합친다.
  - 실제로는 1배다. 한국어 데이터가 늘어난 S1에서는 실제 입력 약 60개당 무효 1개다.
  - S1의 효과를 섞지 않으려고 S1에서는 그대로 두고, 다음 단계(§4 valid 3분류)에서 고친다.

## 1. 지금 학습의 약점 (모델 0.6, 0.6a 실험에서 확인)

| 약점 | 근거 | 설계 |
|---|---|---|

| 손실 가중치가 모두 1 | 과제별 크기 차이(sym 1.3, organ 0.06)를 조정하지 않음 | §4 가중치 |

## 2. 데이터 계약과 학습 전 검사

학습 스크립트가 시작할 때 아래를 검사하고, 하나라도 틀리면 멈춘다.

- **언어:** 증상 문장의 `lang`과 실제 문자가 일치한다(위반 0).
- **개수:** 파일별 행 수와 해시가 `data/curated/judge2/MANIFEST.json`과 같다. 데이터를 바꿀 때만 manifest를 다시 쓴다.
- **gold 격리:** gold 개념과 그 상하위 개념은 organ·align 목표에 0건이다(지금도 검사함, 개수를 로그에 남김).
- **중복과 충돌:** 같은 텍스트가 다른 개념이나 다른 판정(유효/무효)에 붙으면 목록으로 남긴다.
- **분할 누수:** dev·test gold 질의, `koeval_*`와 문자열이 같거나 편집 거리 2 이내인 학습 텍스트는 0건이다.

## 3. 데이터 구성

| 출처 | 쓰는 출력 | 지금 | 바꿀 점 |
|---|---|---|---|
| MONDO 이름·동의어 (`organ_head.texts`) | organ, align | 약 6만 | 개념별 상한(동의어 많은 개념 쏠림 방지) |
| KCD 한국어 이름 → 영어 KCD 벡터 | align | 52,626 중 표본 2만 | 전부 쓰고 개념 단위로 분할 |
| 프로필 이름·일상어·약어 | organ, align, sym | 790개 | 그대로 |
| 증상 문장 (`sym_*`) | sym | 7,890 | 그대로 |
| 한국어 표현 (`ko_*`) | organ, align | 4,849 | 빈도 상위 개념 밖으로 넓힘 |
| 무효 입력 (`junk_*`) | valid | 2,344 ×4 | 어려운 음성 추가(아래) |

| **새로 만듦:** 비질환 의료 상태 | organ, valid | 0 | 시술 후, 약물 노출, 기구 삽입 600개 |

**어려운 음성(무효):** 생성 후 Opus 대조 검토를 거친다. 지난번과 같은 숨은 대조 방식을 쓴다.

- 의학 단어처럼 보이지만 질환이 아닌 말: 병원 이름, 검사실 이름, 약국 영업시간 질문.
- 질환명이 들어 있지만 환자 정보가 아닌 말: 가족이 아닌 남의 이야기, 뉴스 문장, 드라마 대사.
- 한국어 구어 잡담 중 증상 단어를 비유로 쓴 말: "머리 아픈 숙제", "속 터져".

**모호 입력:** 두 개 이상의 흔한 질환으로 읽히는 약어(`as`, `ca`, `ms`, `pd`, `ra`)와 짧은 한국어(`전이`, `염증`, `혹`). 정답은 "되물음"과 후보 질환 목록이다.

## 4. 출력과 손실

| 출력 | 형태 | 손실 | 비고 |
|---|---|---|---|
| valid | 3분류: 실제 / 모호 / 무효 | CE, 클래스 가중 | 지금은 2분류 |
| align | SapBERT 공간 768차원 | InfoNCE(τ=0.05) + 코사인 | in-batch 음성에 더해 MONDO 형제 개념을 어려운 음성으로 |
| organ | 13개 sigmoid | BCE | 다계통 질환 라벨이 검토로 늘었으므로 장기별 pos_weight |
| sym | 790개 softmax | CE | 그대로 |

- **가중치:** 처음 200 step의 손실 크기로 나눠 맞춘 뒤 고정한다. 지금은 sym 1.3과 organ 0.06이 같은 가중치라 사실상 sym이 학습을 끈다.
- **organ의 두 길:** organ head의 직접 출력, 그리고 align으로 찾은 MONDO 개념의 라벨. 단일 모델에서도 둘 다 Gemma에서 나오므로 둘을 비교해 정한다(§7 ablation).

## 5. 모델 선택

epoch마다 선택 분할에서 복합 점수를 잰다. 가장 높은 checkpoint를 쓴다.

    score = 0.35 · organ macro-F1 + 0.35 · align top-1 + 0.15 · valid balanced-acc + 0.15 · sym top-3

gold dev는 선택에 쓰지 않는다. 기록만 한다. 하이퍼파라미터 탐색 결과를 고를 때만 gold dev를 보고, 그 횟수를 문서에 남긴다.

## 6. 분할과 보정

- **개념 단위 분할:** 학습 80% / 선택 10% / 보정 10%. 같은 개념의 영어·한국어·동의어는 같은 쪽에 둔다. 지금은 선택과 보정이 같은 10%다.
- **organ:** 보정 분할에서 장기별 temperature를 맞춘다. 임계값은 F1 최대점이 아니라 bootstrap 200회의 중앙값으로 정한다. 실행 간 흔들림이 줄어든다.
- **valid:** 보정 분할에서 "무효 수락률 ≤ 1%"를 만족하는 가장 낮은 임계값의 bootstrap 상한을 쓴다. 앱의 0.95 고정값과 비교한다.
- **align 거부:** 최근접 MONDO 개념과의 코사인이 τ보다 낮으면 "이해 못 함". τ도 보정 분할에서 정한다.

## 7. 실험 순서와 비용

학습 1회 약 25분, 앱 전체 평가 약 10분. GPU 2장이면 시간당 약 3회다.

| 단계 | 내용 | 실행 |
