## 5. 모든 개념 라벨링과 빠른 장기 판정 (앱 0.3.7, 모델 0.4)

### 5-1. 왜 장기가 비었나

색인의 사람 질환 개념 23,264개 중 3,688개(16%)가 장기 없이 남아 있었다. 원인은 둘이다.

1. **분류 규칙 (설계):** 생식기, 유방, 정신 질환은 13개 축 밖이다. 해당 개념은 약 540개다.
2. **라벨이 없던 개념:** 약 2,800개는 학습 모델이 비워 두었다. 희귀 유전질환 1,393개, 종양 993개가 대부분이다. 흔한 질환 중에서도 치매, Cushing 증후군, 기저세포암, 후각 상실, 만성 치주염이 비어 있었다.

### 5-2. 라벨링 (Haiku 5.5 에이전트 100개)

- 규칙을 보완했다(`GUIDE.md` v3):
  - 치매와 신경발달 질환(자폐, ADHD, 지적장애) → 신경
  - 구강·치아 → 위장관
  - 후각·미각 → 신경
  - 내분비 증후군 → 대사·내분비
  - 피부암 → 피부
- 라벨이 없던 사람 질환 개념 17,051개와, 기존 라벨이 "장기 없음"이던 409개를 다시 판정했다.
- 결과: 16,831개 라벨, 보정 일치율 0.89. 판단 불가 454개, batch 1개는 보정 미달로 제외했다.
- 전체 라벨은 4,601개에서 약 21,000개가 되었다(`labels/verified_v3.jsonl`).
- 장기 모델 단독(개념 수준) test F1: 0.668 → 0.719 (crosswalk 0.625).

## 6. Gemma 장기 판정 모델 (앱 0.3.8, 모델 0.5)

Jev(TypeSafe의 decision model)와 같은 형태다. 텍스트를 생성하지 않고 정해진 답(13개 장기)의 확률만 낸다. 큰 모델(Haiku) 라벨로 증류했다.

- **몸체:** Gemma 4 E2B (Apache-2.0, revision d29ff6b), 텍스트 decoder만 사용.
- **학습:** LoRA r=16(q,k,v,o,gate,up,down) + 13출력 head, bf16, 2 epoch.
- **학습 문장 69,490개:**
  - 영어: 이름·동의어, 검토 질의, 말뭉치 멘션
  - 한국어 3,862개: profile의 이름·일상어·증상
  - gold 개념과 그 부모·자식은 뺐다.
- **보정:** 학습에서 뺀 개념 10%로 장기별 temperature와 기준값을 정했다.

| 설정 (gold dev macro-F1) | 단독 | 링커 + 빈 곳 채움 |
|---|---|---|
| 작은 head (모델 0.4) | 0.803 | 0.835 |
| Gemma 18층 | 0.864 | 0.873 |
| Gemma 35층 | 0.879 | 0.873 |

18층과 35층이 링커와 결합하면 같아서 18층을 골랐다. 크기와 시간이 절반이다. 한국어 예: 당뇨 → 대사, 콩팥병 → 신장, 치매 → 신경, 중풍 → 심혈관+신경, 통풍 → 대사+근골격.

### 양자화 (`ml/gemma_export.py`, `ml/gemma_runtime.py`)

- **층 자르기:** 35층 중 18층만 남기고, 층별 단어표도 그 18층 열만 남겼다. 잘라낸 모델은 학습 모델과 같은 출력을 낸다(cosine 1.0).
- **채택한 방식:** 가중치 int8(행마다 scale) + bf16 계산(PyTorch weight-only int8 kernel).

| 시도 | 결과 | 판정 |
|---|---|---|
| 동적 int8 (입력도 int8) | MLP 입력의 큰 값 때문에 판정이 대부분 바뀜 | 기각 |
| 층별 단어표 4-bit | 출력 cosine 0.99 | 기각 |
| **가중치 int8 + bf16 계산** | 학습 모델과 같은 장기 집합 97% | **채택** |

| 항목 | 값 |
|---|---|
| 파일 | 2.38 GB (2개) |
| 메모리 | 약 3.1 GB |
| CPU 8스레드 | 질의당 약 93 ms |
