# 처음부터 만드는 판정 모델 (X 단계)

2026-10-18. Gemma 같은 사전학습 모델 없이, 무작위 초기값에서 우리 데이터만으로 학습하는 판정 모델이다. UMLS가 들어오면 그 데이터도 쓴다.

## 구성

| 파일 | 역할 |
|---|---|
| `ml/judge_data.py` | 학습 데이터. Gemma 학습(`gemma_judge2.py`)과 같은 출처, 필터, 학습 전 검사를 쓴다. 차이는 두 가지다: gold 개념 id를 항목에 붙이지 않고, 평가 문제와 같은 텍스트는 개념과 상관없이 뺀다. 같은 질환 이름 쌍(MONDO 동의어, 한영 MONDO 이름, KCD 한영 이름, 학습 텍스트와 그 개념 이름, UMLS)도 만든다 |
| `ml/scratch_judge.py` | tokenizer와 모델을 학습하고 보정까지 한다. 결과는 `$ADCTOX_CACHE/scratch_judge_<tag>/`, 기록 카드는 Gemma와 같은 장부에 남는다 |
| `ml/umls_build.py` | UMLS를 학습 파일로 바꾼다. 결과는 `data/curated/external/umls/`(git 제외) |
| `tests/test_umls_build.py` | 만든 가짜 UMLS 5개념으로 gold 격리와 라이선스 필터를 확인한다 |
| `ml/bench_judge.py --system scratch` | 같은 벤치마크로 채점한다 (`SCRATCH_DIR`) |

**모델**
- 입력: 텍스트를 NFD로 바꾼다. 한글 음절이 자모로 풀리므로 오타는 기호 한두 개만 바뀐다.
- tokenizer: 우리 텍스트로 학습한 BPE, 16,000개.
- encoder: 6층, 폭 384, 1,690만 파라미터, 무작위 초기값.
- 출력: valid, 장기 13개, 검색 벡터 256차원.

**학습**
1. 같은 질환 이름끼리 가깝게(InfoNCE, 쌍 21만 개, 6 epoch).
2. 장기와 valid 학습. 1단계 손실도 계속 함께 건다(6 epoch).

**보정:** Gemma와 같다. 장기별 temperature와 threshold, valid threshold를 쓴다. θ(가까운 MONDO 이름의 장기를 쓸지 정하는 기준)는 학습에서 뺀 10% 개념으로 정한다. 평가 문제는 쓰지 않는다.

학습은 GPU 1장으로 seed당 약 25분이다.

## UMLS 변환 규칙 (`ml/umls_build.py`)

- **질환 범위:** Disorders 의미군(DISO). 언어는 ENG, KOR. 숨김(suppressed) 이름은 뺀다.
- **라이선스:** 출처 제한 등급 SRL 0만 기본으로 쓴다. SNOMED CT(등급 9)는 한국 이용 조건을 확인한 뒤 `--srl 0,9`로 켠다.
- **gold 격리:**
  - gold 개념이나 그 상하위에 연결된 UMLS 개념은 통째로 뺀다.
  - 연결이 없어도 이름 하나가 gold 개념의 이름이나 동의어와 같으면 뺀다.
  - 평가 문제와 같은 이름은 뺀다.
- **출력:**
  - `pairs.jsonl`: 개념마다 대표 영어 이름과 다른 이름 최대 10개. 한국어와 약어를 먼저 넣는다.
  - `items.jsonl`: 라벨이 있는 MONDO 개념 하나에만 연결된 UMLS 개념의 모든 이름. 장기 라벨은 MONDO에서 가져온다.
- **사용:** 파일이 있으면 `judge_data`가 자동으로 쓰고(`--drop umls`로 뺄 수 있음), 기록 카드의 `umls` 항목에 행 수와 sha256이 남는다.

**UMLS를 받으면:**

```bash
ADC_RESEARCH_MODE=1 python ml/umls_build.py --meta data/raw/umls/<버전>/META
CUDA_VISIBLE_DEVICES=0 ADC_RESEARCH_MODE=1 ADCTOX_CACHE=<cache copy> python ml/scratch_judge.py --tag x1s7 --seed 7 --stage "X1 from scratch + UMLS" --compare-to x0s7
```

## X0 결과: UMLS 없이 (dev, seed 3개)

| 시스템 | 영어 장기 F1 | 한국어 장기 F1 | 영어 개념 | 한국어 개념 | 무효 수락 |
|---|---|---|---|---|---|
| 튜닝 안 한 Gemma | 0.761 | 0.764 | 0.44 | 0.42 | 0 |
| 튜닝한 Gemma (S2d) | 0.861 | 0.803 | 0.42 | 0.30 | 0 |
| **처음부터 (X0)** | **0.463** | **0.577** | 0.28 | 0.22 | 0.067 (30개 중 2개) |

| 유형 | X0 영어 | X0 한국어 |
|---|---|---|
| canonical | 0.50 | 0.61 |
| synonym | 0.54 | 0.71 |
| abbrev | 0.12 | 0.23 |
| typo | 0.40 | 0.52 |
| lay | 0.58 | 0.68 |

**해석**
1. **사전 지식이 없으면 처음 보는 질환을 판정하지 못한다.**
   - 평가 질환(gold와 그 상하위)은 학습에서 빠져 있다. Gemma는 사전학습에서 이 질환들을 이미 알고 있어서 튜닝하지 않아도 0.76이다.
   - 처음부터 만든 모델은 이름의 글자 조각만으로 추측해야 해서 0.46/0.58에 그친다.
2. **이 모델에서는 한국어가 영어보다 높다(+0.11).**
   - 한국어 의학 용어는 한자 조합이라 글자에서 장기가 보인다(신/콩팥, 간, 폐, 안). 반면 영어 질환명은 라틴어·그리스어 어근과 고유명사가 많다.
   - 처음부터 만든 모델이 한국어의 이 구조를 쓴다는 근거다.
3. **약어는 사실상 못 맞힌다(0.12/0.23).** 약어는 글자에 정보가 없어서, 그 약어를 학습에서 봤어야만 맞힐 수 있다.
4. **valid 거르기도 약하다.** valid threshold가 0.995까지 올라가 실제 질환의 약 20%를 거른다. 그래도 무효 입력 2개를 받아들인다. 다만 이 거르기를 꺼도 점수는 거의 같았다(영어 0.45, 한국어 0.62). 약점은 장기 판정 자체에 있다.

## UMLS가 메울 수 있는 것과 없는 것

- **메울 것:** 영어 이름과 약어. 평가 질환의 형제 질환과 같은 약어를 쓰는 다른 질환이 대량으로 들어온다. 지금 가장 약한 abbrev와 영어 전반이 오를 것이다.
- **못 메울 것:** gold 질환 자체는 UMLS에서도 빠진다. 그래서 처음 보는 질환을 판정하는 능력은 여전히 이름의 구성과 비슷한 질환에서 와야 한다.
- **예상:** 튜닝한 Gemma와의 차이(영어 −0.40, 한국어 −0.23)를 UMLS만으로 다 메우기는 어렵다. 실제로 얼마나 줄어드는지는 X1에서 숫자로 보고, X0 대비 기여도도 함께 남긴다.

## 다음 후보 (X1 이후)

- **모델 키우기:** 1,690만 → 약 1억 파라미터, epoch 늘리기. 지금은 epoch 3–4에서 val loss가 멈춘다.
- **글자 가리고 맞히기 사전학습:** MONDO, UMLS, KCD, 의학 텍스트 말뭉치로 이름의 구조를 먼저 배운다.
- **조합:** 한국어 정식 이름은 처음부터 모델의 장점(글자 구성)을 쓰고, 나머지는 Gemma가 맡는다. 두 모델의 장기 확률을 섞어 보는 시험.
