## 3. 원인

**3-1. 한국어 질환을 "질환 아님"으로 거른다 (가장 큼)**
- 정답이 있는 dev 문제 261개 × seed 3개 = 783번 중 영어는 20번, 한국어는 **63번**을 무효로 걸렀다.
- 걸린 예: `급성신손상`, `뾰루지`, `백반증`, `편두퉁`, `대상포짐`, `결헥`, `크론벵`처럼 짧은 한국어 이름과 오타.
- 거른 문제가 모두 맞았다고 치면 한국어는 0.775 → **0.819**, 영어는 0.879 → 0.890이 된다. 이 하나로 한영 차이의 약 1/3이 설명된다.
- **이유:** junk의 80%(1,872/2,344)가 한국어이고 대부분 짧다(`ㅋㅋㅋ`, `ㅇㅇ`, 음식, 장소). 반면 짧은 한국어 질환 이름(2–4음절)은 학습에 적다. 그래서 모델이 "짧은 한글 = 무효"를 배웠을 가능성이 크다.

**3-2. 한국어 오타가 영어 오타보다 훨씬 어렵다**
- 영어 오타는 항목 1,134개뿐인데도 0.893이다. Gemma가 사전학습에서 영어 철자 변형을 많이 봤기 때문이다.
- 한국어 오타는 음절 안의 자모가 바뀐다(`뱅/벵/벙` ← 병, `퉁` ← 통, `헥` ← 핵, 받침 누락/추가, 마지막 음절 잘림, `ㅇ` 덧붙임). 토큰이 통째로 달라져서 모델이 같은 단어로 알아보기 어렵다.
- 지금 한국어 오타는 Haiku가 개념당 2개씩 만든 4,253개(2,133개념)이다. 대부분의 한국어 이름(약 1만 5천 개념)에는 오타 예가 없다.

**3-3. 한국어 약어가 사실상 없다**
- 한글 약어(`갑저`, `고지혈`, `협심`, `심부전 hx` 등)는 33개뿐이다. 한영 혼합(`DM 2형`, `HTN 있음`, `CKD 4기`, `r/o 결핵`)도 약어와 오타에서 거의 없다.
- 한국 임상 기록은 한영 혼합이 흔하다. 한국어 평가 문제에서도 혼합이 23개, 영어만 쓴 문제가 46개다.

**3-4. 장기별로 한국어 일상어가 고르지 않다**
- 한국어 일상어가 있는 개념은 otologic 88, renal 180, hepatic 148로 적고, infectious_immune은 738로 많다.
- dermatologic은 335개념에 일상어가 있지만, 흔한 피부 질환의 일상 이름(`뾰루지`, `두드러기`, `습진`, `무좀`)이 짧아 3-1에 함께 걸린다.

**3-5. 평가 문제 자체의 한계 (데이터를 만들기 전에 확인할 것)**
- 한국어 평가 문제는 영어 gold 600개를 LLM이 번역한 것이다(`koeval_*`, 사람 검수 없음). 유형은 영어 원문을 따른다.
- 그래서 실제 한국어 입력과 다른 문제가 섞여 있다.
  - "약어"인데 단어를 자른 것: `편두`(migr), `심상성 여`(acne vulg), `흉삼`(pl eff)
  - "오타"인데 맞는 표기: `폐색성 수면무호흡증`, `클로스트리디움 디피실 감염`
  - 원래 다른 뜻인 말: `주사`(rosacea 오타로 의도했지만 보통 injection), `백반`(밥상)
- 이 문제들은 사람도 알아보기 어렵다. 모델 출력을 보지 않은 채로 "한국어 사용자가 이 질환으로 알아볼 수 있나"만 판정하는 검토가 필요하다. 모델 점수를 보고 문제를 고르면 평가가 오염된다.

## 4. 만들 데이터와 기준

모든 생성 데이터의 공통 기준(지금 파이프라인 그대로):
- gold 개념과 그 상하위는 대상에서 뺀다. 학습 전 유출 검사를 통과해야 한다.
- LLM 생성은 두 번째 패스로 검증하고, 일부러 틀린 문장을 6% 섞어 0.75 이상 잡아낸 배치만 반영한다.
- 출처 이름을 따로 붙여 `--drop`으로 빼 볼 수 있게 하고, 기록 카드에 행 수와 sha256을 남긴다.

| 순서 | 데이터 | 만드는 방법 | 기준 | 겨냥하는 원인 |
|---|---|---|---|---|
| D1 | **짧은 한국어 질환 이름을 유효 입력으로** | 기존 mondo_ko, KCD, ko2, 프로필에서 2–4음절 이름을 골라 valid=1로 추가. 새로 만들지 않음 | 장기 라벨이 있는 개념만 | 3-1 |
| D2 | **junk 언어 균형** | junk를 한국어와 영어 비율이 실제 입력에 가깝게 다시 표본 추출. 4배 oversampling이 dedupe에서 사라지는 버그도 고침 | 무효 입력 수락 0 유지(junk val 기준) | 3-1 |
| D3 | **규칙 기반 한국어 오타** | 한글을 자모로 분해해서 두벌식 자판 인접 키, 모음 혼동(ㅔ/ㅐ, ㅗ/ㅓ), 받침 누락·추가·교체, 마지막 음절 잘림, 띄어쓰기 변형을 적용. LLM 없이 seed 고정으로 재현 가능 | 자모 편집 거리 1–2. 만든 오타가 다른 질환의 한국어 이름이나 KCD 이름과 같으면 버림 | 3-2 |
| D4 | **한국어 약어와 한영 혼합** | Haiku 생성 + 검증(ko2와 같은 절차). 대상은 한국 임상에서 자주 코딩되는 질환 | 실제로 쓰는 약어만. 다른 뜻이 더 흔하면 생성하지 않음 | 3-3 |
| D5 | **장기별 한국어 일상어 보충** | ko2를 otologic, renal, hepatic, dermatologic, neurologic 쪽으로 확장 | 장기별 일상어 개념 수가 최소 300이 되도록 | 3-4 |
| E1 | **한국어 평가 문제 검토** | 두 명이 따로 "알아볼 수 있나"만 판정(모델 출력 안 봄). 못 알아보는 문제는 고쳐 쓰거나 표시 | 바꾼 문제와 이유를 모두 기록. 영어 gold와 라벨은 그대로 | 3-5 |

D1–D3은 새 LLM 호출이 필요 없다. D4와 D5는 Haiku를 쓴다(앞서 허용한 200개 중 152개 사용, 48개 남음).

### 해석
1. **한국어 데이터를 늘려도 한국어 점수는 거의 안 움직인다.**
   - S2b: 오타를 2만 6천 개 넣었는데 한국어 typo F1이 0.682 → 0.680으로 그대로다.
   - S2c: 약어와 혼합 표현을 6천 개 넣었는데 abbrev 0.758로 같다.
   - 평가 질환(gold와 그 상하위)은 학습에서 빠져 있으므로, 다른 질환의 한국어 예는 처음 보는 질환으로 거의 옮겨 가지 않는다.
2. **튜닝 효과는 영어에만 생긴다.**
   - 튜닝 안 한 Gemma는 한국어와 영어가 같다(0.764 대 0.761).
   - 튜닝 후 영어는 +0.11, 한국어는 +0.02~0.04다.
   - 정자로 쓴 한국어 정식 이름도 0.82로 영어(0.90)보다 낮다.
   - 즉 모델 안에서 한국어 이름과 영어 이름이 같은 질환으로 묶이지 않아, 영어에서 배운 장기 지식이 한국어로 넘어가지 않는다.
3. **두 언어를 직접 묶는 방법만 효과가 있었다.**
   - 일관성 학습(S2d)이 처음으로 한국어를 올렸다. 한국어 +0.012, 개념 정답 +0.06, typo +0.022.
   - 대신 영어가 −0.011 내려갔다.
   - 번역을 붙이는 방법도 같은 방향으로 효과가 있다.
