# Gemma 판정 모델: 무엇을 추가로 학습시켰나

ADCTOX는 환자의 기저질환을 입력받아 13개 장기 축 중 어디가 약한지 정한다. 이 판단을 하는 모델이 Gemma 판정 모델이다.
이 문서는 공개 모델 위에 이 프로젝트가 직접 만든 부분을 구분해 정리한다.

## 1. 한눈에 보기

| 구분 | 가져다 쓴 것 (공개) | 이 프로젝트가 만든 것 |
|---|---|---|
| 언어 모델 | Gemma 4 E2B (Google, Apache-2.0)의 텍스트 부분 | 앞 18층만 쓰는 구조, LoRA 어댑터, 판정 출력 4종 |
| 질병 체계 | MONDO 온톨로지, HPO, HIRA KCD 한국어 병명 | 사람 질병 21,032개의 13개 장기 라벨 |
| 질병 연결 | SapBERT (영어 질병명 임베딩) | 후보 재정렬 모델, Gemma에서 SapBERT 공간으로 가는 한국어 연결 |
| 학습 문장 | 외부 말뭉치 (MedMentions, NCBI, BC5CDR, COMETA) | LLM으로 생성하고 검수한 증상 문장, 한국어 표현, 무효 입력 예시 |
| 평가 | — | gold 600문항 (dev/test 분리), 한국어 평가 600문항, 증상 평가 206문항 |
| 배포 | PyTorch int8 커널 | 층 자르기와 int8 양자화, CPU 런타임 (2.4 GB, 입력당 약 0.1초) |

**한 줄 요약:** 범용 LLM에 질문하는 방식이 아니다. LLM 에이전트가 만든 대규모 라벨을 증류해서, 이 프로젝트 전용 판정 모델을 만들고 오프라인으로 돌린다.
- 판정 대상은 13개 장기, 무효 입력, 한국어, 증상이다.
- 판정 모델은 문장을 생성하지 않는다. 확률만 낸다.
- 평가는 학습과 분리된 dev/test 세트로 한다.

## 2. 모델 구조

```
입력: "Condition: <사용자 입력>\nOrgans it directly affects:"
  → Gemma 4 E2B 텍스트 디코더, 35층 중 앞 18층 (LoRA r=16: q,k,v,o,gate,up,down)
  → 마지막 토큰의 은닉 상태 1,536차원
      ├─ organ : 13개 장기 확률         (장기마다 온도 보정과 임계값)       ← 모델 0.5부터
      ├─ valid : 실제 입력일 확률        (질병, 증상, 병력 vs 입력 오류)     ← 모델 0.6
      ├─ align : SapBERT 공간의 768차원 벡터 (기존 MONDO 색인으로 연결)   ← 모델 0.6
      └─ sym   : 질병 프로필 790개 중 어느 질병인지 (증상 설명 → 질병)     ← 모델 0.6
```

- **학습되는 파라미터:** 약 1,300만 개(LoRA와 출력층)이다. Gemma 원본 가중치는 고정이다.
- **18층만 쓰는 근거:** 35층 전체와 dev 성능이 같았다(0.873 vs 0.873). 크기와 시간은 절반이다.

## 3. 출력별 학습 내용

### 3.1 organ: 질병 → 13개 장기 (Jev 방식 증류)

- **목표값:** MONDO 사람 질병 21,032개의 장기 라벨이다.
  - 1차: Haiku 50개 에이전트가 4,465개를 검증했다.
  - 2차: Haiku 100개 에이전트가 16,831개를 채웠다.
  - 기준은 `data/curated/concept_organs/GUIDE.md` v3에 있다.
- **라벨 품질 관리:**
  - 배치마다 정답을 아는 개념을 섞었다. 정답과 일치한 비율은 평균 0.89였다.
  - 일치율이 0.6 미만인 배치는 버렸다(100개 중 1개).
  - 판단이 애매하다는 답(454개)은 쓰지 않았다.
- **학습 문장:**
  - MONDO 이름과 동의어, 검수한 사용자식 질의, 외부 말뭉치의 질병 언급
  - 질병 프로필의 한국어 이름, 일상어, 증상
  - 모델 0.6은 여기에 Haiku가 만든 한국어 표현과 증상 문장을 더했다.
- **보정:** 학습에서 뺀 개념 10%로 장기마다 온도와 임계값을 정했다.

### 3.2 valid: 입력이 실제 내용인지 (모델 0.6)

- **양성:** 위의 모든 질병, 증상, 병력 문장이다.
- **음성:** Haiku가 만든 "질병이 아닌 입력" 2,500개다(한국어 1,500개 포함). 이 중 10%는 임계값을 정하는 데만 썼다.
  - 예시: ㅁㄴㅇㄹ, 없음, 해당없음, 홍길동, 바나나, 테스트123, 이모지
- **역할:** 기존 SapBERT 기반 판정은 한국어를 대부분 무효로 걸렀다. 이 출력은 언어와 상관없이 판정한다.
- **임계값 결과:** 0.995. 학습에 쓰지 않은 실제 문장의 98.6%를 받아들이고, 학습에 쓰지 않은 무효 입력은 하나도 통과시키지 않는다.

### 3.3 align: 한국어 → MONDO 연결 (모델 0.6)

- **목표:** 입력 문장의 질병을 SapBERT가 만든 질병명 벡터와 같은 공간에 놓는다. 그러면 기존 MONDO 색인(95,437행)을 그대로 쓸 수 있다.
- **학습 쌍:**
  - HIRA KCD 한국어 병명 16,275개 → 그 영어 KCD 병명의 SapBERT 벡터
  - Haiku가 만든 한국어 표현 4,983개(질병 1,566개) → 해당 MONDO 개념의 벡터
  - 영어 학습 문장 → 해당 개념의 벡터
- **손실 함수:** 배치 안 대조 학습(InfoNCE, τ=0.05)과 코사인 손실을 함께 썼다.
- **한계:**
  - 학습에서 본 적 없는 개념을 정확히 찾는 비율은 50%이고, 한국어만 보면 25%다.
  - 그래서 KCD 사전으로 찾지 못한 한국어 입력에만 보조로 쓴다(유사도 0.6 이상).

### 3.4 sym: 증상 설명 → 질병 (모델 0.6)

- **학습 문장:** Haiku가 질병 790개마다 10개씩 쓴 증상 설명 7,900개다.
  - 언어: 한국어 일상어 4, 한국어 진료기록체 2, 영어 일상어 2, 영어 진료기록체 2
  - 10개 중 8개 이상은 질병명을 쓰지 않았다.
- **분리:** 생성 에이전트는 증상 평가셋(`symptom_eval_v0`)을 보지 않았다.
- **앱에서 쓰는 방식:** 기존 n-gram과 BioLORD 점수에 더한다. 가중치 4는 증상 평가 dev 절반에서 골랐다.

## 4. 데이터 분리 원칙

- **평가셋은 학습에 쓰지 않았다.**
  - gold 평가셋의 개념과 그 상위·하위 개념은 organ과 align 학습에서 뺐다.
  - 한국어 평가셋(gold 질의를 Sonnet이 옮긴 것)은 학습에 쓰지 않았다.
- **설정은 dev에서만 골랐다.** 임계값과 가중치가 해당한다. test는 최종 보고 때만 본다.
- **신뢰구간:** 개념 그룹 단위로 묶은 paired bootstrap 95% CI로 낸다.

## 5. 결과

모두 앱 전체 파이프라인(`recommend.resolve`)의 장기 macro-F1이다. 설정은 dev에서 골랐고, test는 배포 직전에 한 번 확인했다.

| 평가 (test) | 이전 | Gemma 판정 | 차이 [95% CI] |
|---|---|---|---|
| 장기 판정, 영어 gold | 0.811 (모델 0.4) | 0.832 (모델 0.5, organ만) | +0.021 [+0.005, +0.037] |
| 장기 판정, 영어 gold | 0.832 (모델 0.5) | **0.841** (모델 0.6, 출력 4종) | +0.009 [−0.002, +0.022]: 떨어지지 않음 |
| 장기 판정, 한국어 gold | 0.429 (모델 0.5) | **0.733** (모델 0.6) | **+0.304 [+0.229, +0.384]** |
| 증상 → 질병 top-3 (증상 평가) | 0.763 | **0.839** (모델 0.6) | top-1 0.415 → 0.661 |
| 무효 입력 통과 (영어, 한국어) | 0, 0 | **0, 0** | — |

이 프로젝트 시작 시점과 비교하면 영어 gold test는 0.660 → 0.747(재정렬) → 0.811(전체 라벨) → 0.832(Gemma) → 0.841(출력 4종)로 올랐다.

**유효 입력 임계값을 정한 과정**

| 후보 | 질병이 아닌 입력 예시 | 임계값 | 한국어 dev F1 | 한국어 무효 입력 통과 (dev) |
|---|---|---|---|---|
| v2 | 1,000개 | 0.95 | 0.763 | 2/15 |
| v3 (배포) | 2,500개 (한국어 1,500개 추가) | 0.995 | 0.708 | **0/15** |

- v2에서 통과한 두 건은 "로렘 입숨"(유효 입력 판정이 받아들임)과 "거부"(KCD 사전이 거부반응으로 연결)였다.
- 그래서 v3는 한국어 입력 오류 예시를 1,500개 더 만들어 다시 학습했다. dev와 같은 문장 2개는 생성 결과에서 지웠다.
- 임계값은 학습에 쓰지 않은 입력 오류 예시를 모두 거르는 가장 낮은 값으로 정했다.
- 결과적으로 점수는 조금 낮아졌다(dev 0.763 → 0.708). 대신 무효 입력을 하나도 통과시키지 않는 쪽을 택했다.

## 6. 실행 환경

| 항목 | 값 |
|---|---|
| 양자화 | 가중치 int8(행마다 스케일 1개), 계산 bf16 |
| 원래 모델과 일치율 | 0.5: 97%, 0.6: 97.2% |
| 크기 | 2.4 GB |
| 앱 전체 최대 메모리 | 3.9 GB |
| 속도 | CPU에서 입력당 약 0.1초 |
| 지원 OS | Linux, macOS(Apple silicon), Windows |

환자 입력은 외부 서버로 나가지 않고 사용자 PC 안에서만 처리된다.

기각한 방식:
- 동적 int8: 입력값도 양자화하면 MLP에서 판정이 대부분 바뀌었다.
- 단어표 4-bit: 오차가 너무 컸다.

## 7. 한계

- 라벨은 모두 LLM이 만들었다. 전문가가 검증하지 않았고, 정답과 일치한 비율은 0.89다.
- gold 평가셋, 한국어 평가셋, 증상 평가셋 모두 기계가 만든 합성 질의다. 실제 사용자 입력으로 한 평가는 아직 없다.
- gold test는 여러 번 열람했다. 설정은 모두 dev에서 골랐지만, 다음 개선은 새 평가셋으로 확인하는 것이 맞다.
