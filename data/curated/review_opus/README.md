# 학습 데이터 전수 검증 (Claude Opus 5.5, 2026-10-17)

Gemma 판정 모델과 질환 검색이 쓰는 데이터셋 여섯 개를 Opus 에이전트 286개가 세 번에 걸쳐 검토했다.
모든 묶음에 정답을 아는 숨은 대조 항목을 섞어 에이전트를 채점했고, 대조 항목을 통과한 묶음의 변경만 반영했다.
대조 항목 자체는 데이터에 쓰지 않는다. gold 평가셋의 개념과 그 상하위 개념은 대조 항목으로만 나온다.

## 1차: 전수 검토 (200개 에이전트, 37분)

| 데이터 | 항목 | 대조 항목 | 대조 통과 | 결과 |
|---|---|---|---|---|
| 장기 라벨 (`concept_organs/labels/`) | 21,031 | gold 라벨 8개/묶음, 절반은 일부러 틀리게 보여 줌 | 106/106 | 변경 429, 판단 불가 28 |
| 증상 문장 (`judge2/gen/sym_*`) | 7,900 | 다른 질환 문장 5개/묶음 | 32/32 | 수정 564, 삭제 10 |
| 한국어 표현 (`judge2/gen/ko_*`) | 4,983 | 다른 개념 아래 둔 표현 5개/묶음 | 20/20 | 수정 378, 삭제 146 |
| 무효 입력 (`judge2/gen/junk_*`) | 2,498 | 실제 증상·병명 6개/묶음 | 7/7 | 실제 입력이라 삭제 16 |
| 질환 프로필 (`disease_profiles/`) | 790 | 다른 프로필 이름을 붙인 3개/묶음 | 20/20 | 수정 121 |
| 한국어 MONDO 이름 (`korean/mondo_ko.jsonl`) | 4,410 (확신 낮음 537 전부 + 중간 표본) | 다른 개념 이름으로 바꾼 6개/묶음 | 15/15 | 수정 174 |

장기 라벨 대조에서 에이전트는 gold가 한 장기만 적은 다계통 질환(SLE, 쇼그렌, 사르코이드증)에 장기를 더 붙였다.
GUIDE의 "직접 침범하는 장기를 모두" 규칙에 맞는 판단이라, gold 장기를 모두 포함하는 변경은 맞는 답으로 채점했다.

## 2차: 변경 재검증, 나머지 이름, 블라인드 재라벨 (83개 에이전트, 19분)

- **변경 재검증:** 1차에서 학습 목표나 표시 이름을 바꾼 1,258건을 A/B로 섞어 어느 쪽이 맞는지 다시 물었다(어느 쪽이 기존 값인지 모름). 1,226건은 새 값, 12건은 둘 다 가능, **20건은 기존 값**이 맞다고 보아 되돌렸다(장기 5, 한국어 표현 14, 이름 1). 대조 통과율 1.0.
- **한국어 MONDO 이름 나머지 18,785개:** 수정 591, 대조 통과 64/64. 1차와 합쳐 23,258개를 모두 검토했고, 765개를 고쳤다.
- **블라인드 재라벨:** 학습 개념 2,000개를 기존 라벨 없이 다시 라벨링해 기존 라벨과 비교했다. 이것이 라벨 오류율의 추정치다.

| 기존 라벨의 장기 수 | 개념 | 완전 일치 | 기존 라벨 ⊆ 새 라벨 | Jaccard |
|---|---|---|---|---|
| 0 | 395 | 0.901 | 1.000 | 0.901 |
| 1 | 791 | 0.881 | 0.981 | 0.928 |
| 2 | 499 | 0.729 | 0.858 | 0.878 |
| 3 이상 | 300 | 0.623 | 0.787 | 0.868 |

불일치는 대부분 다계통 질환에서 장기를 하나 더 넣느냐의 차이다. 기존 라벨이 새 라벨에 포함되는 비율(⊆)이 높다.

## 3차: 불일치 판정 (3개 에이전트)

블라인드 불일치 381건을 A/B로 판정했다. 새 라벨 232, 기존 라벨 73, 둘 다 가능 76. 새 라벨이 이긴 232건을 반영했다.

## 그 밖에 고친 것

- **동물 질환 215개를 학습에서 뺐다.** MONDO의 비인간 가지(개, 소, 돼지, 원숭이 등)에 장기 라벨이 붙어 있었다. `linking_models.load_organ_labels`가 이제 거른다.
- 무효 입력의 중복 138개를 지웠다.
- 같은 한국어 이름을 쓰던 프로필 두 개의 이름을 구분했다(알츠하이머병 2형, 자가면역 혈소판감소 자반증).
- 판정 에이전트가 지적한 GUIDE의 빈틈을 v4 규칙으로 적었다(`concept_organs/GUIDE.md`).

### 반영 오류와 수정 (2026-10-17)

처음 반영할 때 증상 문장·한국어 표현·무효 입력 파일을 제자리에서 고쳤다. 반영 스크립트가 두 번 돌면서 같은 변경이 밀린 줄 번호에
한 번 더 들어갔다. 다른 문장이 고쳐지고 다른 줄이 지워졌다(영어 증상 문장 230개에 한국어 문장이 들어감). 이 데이터로 학습한 모델은
영어 일상 표현에서 나빠졌다. 이제 `ml/dataset_review_gen.py`가 검토 전 파일(커밋 61faa4d)에서 한 번에 다시 만든다. 몇 번을 돌려도
결과가 같다. `ko_restored.jsonl`은 없어졌다. 되돌린 변경은 처음부터 반영하지 않는다.

학습 스크립트는 그대로 JSONL을 읽는다. 사람이 보기 위한 CSV 사본은 `csv/`에 있다(아래).

## 파일

| 경로 | 내용 |
|---|---|
| `INSTRUCTIONS.md` | 에이전트에게 준 규칙 |
| `out/*.jsonl` | 에이전트 판정 286개 파일. 1차의 `i`는 검토 전 파일(커밋 61faa4d 이전)의 줄 번호다 |
| `manifest.json`, `manifest2.json`, `manifest3.json` | 묶음별 숨은 대조 항목과 정답 |
| `report.json`, `report2.json`, `report3.json` | 묶음별 채점과 집계 |
| `review_queue.csv` | 대조에 실패한 묶음의 변경(이번에는 0건) |
| `csv/organ_labels.csv` | 개념, 이름, 장기, 학습 사용 여부, 검토 결과 |
| `csv/symptom_sentences.csv`, `csv/korean_expressions.csv`, `csv/invalid_inputs.csv` | 판정 모델 학습 문장 |
| `csv/disease_profiles.csv`, `csv/korean_mondo_names.csv` | 검색용 프로필과 한국어 이름 |

묶음 입력(`batches/`, 17 MB)은 저장소에 넣지 않았다. `ml/dataset_review_batches.py`와 `ml/dataset_review_round2.py`가 만든다.

## 재현

```bash
ADC_RESEARCH_MODE=1 python ml/dataset_review_batches.py          # 1차 묶음
# 에이전트 실행 (Claude Code Workflow, model opus) -> out/
ADC_RESEARCH_MODE=1 python ml/dataset_review_merge.py --apply    # 반영, CSV
ADC_RESEARCH_MODE=1 python ml/dataset_review_round2.py           # 2차 묶음
ADC_RESEARCH_MODE=1 python ml/dataset_review_merge2.py --apply   # 되돌리기, 이름 반영, 판정 묶음
ADC_RESEARCH_MODE=1 python ml/dataset_review_merge3.py --apply   # 판정 반영
ADC_RESEARCH_MODE=1 python ml/mondo_ko_batches.py --merge        # 한국어 이름 다시 합치기
```

## 한계

- 검토자는 모두 LLM이다. 전문가 검증은 아직 없다.
- 라벨 오류율 추정(블라인드 2,000개)은 다른 LLM과의 일치율이지 정답과의 일치율이 아니다.
- 모델 0.6은 검토 전 데이터로 학습했다. 이 데이터로 다시 학습한 모델이 다음 단계다.
